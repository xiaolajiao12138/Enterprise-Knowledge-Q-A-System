## 优先处理的问题

### 1. [P1] 默认密钥可伪造管理员身份，现有默认账号也未改密码

位置：[config.py:31](C:/Users/Administrator/Desktop/企业知识问答系统/backend/app/config.py:31)、[deps.py:26](C:/Users/Administrator/Desktop/企业知识问答系统/backend/app/core/deps.py:26)、[init_db.py](C:/Users/Administrator/Desktop/企业知识问答系统/backend/init_db.py)。证据：S01、只读账号检查。

默认 JWT 密钥直接写在源码中。使用该密钥签发 `sub=admin` 的令牌，在完全不经过登录的情况下访问管理员用户接口返回 **200**。令牌不带 `exp` 也被接受。这里的实测针对默认配置；显式设置强随机 `SECRET_KEY` 能消除默认密钥这一触发条件。

另外，交付数据库中的 `admin` 和 `staff` 都仍使用公开的初始密码。即使只修改管理员密码，继续使用默认 JWT 密钥仍可被绕过。

建议：启动时强制要求持久化的随机密钥，拒绝默认值；初始化使用一次性随机密码或显式管理员配置；强制首次改密；校验必需的 `exp`、`sub` 等声明，并设置令牌签发者与受众。

### 2. [P1] 删除账号后，新账号可能继承旧账号聊天记录

位置：[database.py:7](C:/Users/Administrator/Desktop/企业知识问答系统/backend/app/database.py:7)、[users.py:114](C:/Users/Administrator/Desktop/企业知识问答系统/backend/app/api/users.py:114)、[chat.py:11](C:/Users/Administrator/Desktop/企业知识问答系统/backend/app/models/chat.py:11)。证据：S03。

SQLite 没有显式开启外键约束；用户删除时也没有 ORM 级的用户到会话级联关系。`ondelete="CASCADE"` 因而没有清掉旧会话。普通的 `autoincrement=True` 并不等同于 SQLite 表级 `AUTOINCREMENT`，删除最大 ID 后，新用户可能复用该 ID。

实测：删除用户 ID **4**，创建不同用户名的新用户仍得到 ID **4**；新用户会话列表出现旧用户的私密会话，读取消息接口返回 **200**。这是已复现的数据隔离漏洞。

建议：在每个 SQLite 连接开启 `PRAGMA foreign_keys=ON`，补齐用户及会话级联删除；迁移并清理现有孤儿会话；必要时采用不可复用的身份标识。只禁止 ID 复用不能解决孤儿数据残留。

### 3. [P1] 助手消息支持未净化 HTML，可形成存储型 XSS

位置：[聊天页面:116](C:/Users/Administrator/Desktop/企业知识问答系统/frontend/src/views/chat/index.vue:116)、[聊天页面:237](C:/Users/Administrator/Desktop/企业知识问答系统/frontend/src/views/chat/index.vue:237)、[rag_service.py:214](C:/Users/Administrator/Desktop/企业知识问答系统/backend/app/services/rag_service.py:214)。证据：S06、U02。

助手文本直接经 `marked.parse()` 进入 `v-html`。测试 HTML 的 `onerror` 属性完整保留；离线提炼代码也会把文档中的该 HTML 带进助手回答。恶意知识文档或模型返回内容因此可进入浏览器 HTML 注入点，并随聊天记录持久化。令牌保存在 localStorage，若脚本成功执行便可被读取。

已验证内容传递和危险属性保留，未在真实浏览器执行载荷。建议对最终 Markdown HTML 做白名单净化，例如 DOMPurify；限制链接协议及远程资源，并添加合适的 CSP。异常分支也不能直接把原始文本当 HTML 返回。

### 4. [P1] 退出、改密和同名账号重建都不能使旧令牌失效

位置：[auth.py:55](C:/Users/Administrator/Desktop/企业知识问答系统/backend/app/api/auth.py:55)、[users.py:83](C:/Users/Administrator/Desktop/企业知识问答系统/backend/app/api/users.py:83)、[security.py:25](C:/Users/Administrator/Desktop/企业知识问答系统/backend/app/core/security.py:25)。证据：S02。

退出接口仅记日志，重置密码仅修改哈希；JWT 仅用用户名定位用户。实测旧令牌在退出后、管理员重置密码后、删除并重建同名账号后访问 `/auth/me` 均返回 **200**。禁用账号时的即时拦截测试通过，但这不等于退出和改密具有撤销能力。

建议：令牌绑定稳定用户 ID，增加令牌版本或服务器端会话状态；改密、退出和删除账号时使相应会话失效，并防止同名账号复用旧身份。

### 5. [P1] 自动切换向量模型会使知识库维度或语义空间不一致

位置：[vector_store.py](C:/Users/Administrator/Desktop/企业知识问答系统/backend/app/services/vector_store.py)。证据：L05。

外部 embedding 不可用时，入库和查询会静默降级为 384 维哈希向量；服务恢复后又使用配置模型。集合没有绑定所用模型、版本和维度。实测集合以 384 维入库后用 768 维查询，Chroma 报 `Collection expecting embedding with dimension of 384, got 768`。异常发生在模型调用的兜底范围之外，会导致问答失败。同维度但不同模型也存在不可比较的问题。

建议：集合固定 embedding 标识和维度；模型异常应明确失败，或使用独立降级集合；修改模型时执行完整重建并切换集合，不能直接混用。

### 6. [P1] 向量删除或清空失败仍返回成功，已删除文档内容可能继续可检索

位置：[vector_store.py](C:/Users/Administrator/Desktop/企业知识问答系统/backend/app/services/vector_store.py)、[documents.py:114](C:/Users/Administrator/Desktop/企业知识问答系统/backend/app/api/documents.py:114)、[documents.py:178](C:/Users/Administrator/Desktop/企业知识问答系统/backend/app/api/documents.py:178)。证据：L07、L09。

底层向量删除/集合清空异常被捕获后不向上传递。注入存储故障后，删除 API 返回 **200**，关系记录和源文件被移除，但 Chroma 仍保留 **1** 个相关向量。清空故障也返回 **200**，文档切片数改成 **0**，真实向量仍存在。检索链路没有再次核验文档是否仍有效。

建议：传播存储失败，使用可恢复任务状态及幂等重试；确认删除成功后再完成业务状态变更；查询时过滤无效文档。清空成功后也应明确标记文档未索引，避免“completed、0 切片”的歧义。

### 7. [P1] 离线问答会输出缺失关键事实或不对应问题的答案

位置：[rag_service.py:92](C:/Users/Administrator/Desktop/企业知识问答系统/backend/app/services/rag_service.py:92)、[rag_service.py:214](C:/Users/Administrator/Desktop/企业知识问答系统/backend/app/services/rag_service.py:214)。证据：L16、L13。

对项目自带文档实测：

| 问题 | 文档中的必要事实 | 实际离线回答问题 |
| --- | --- | --- |
| 年休假有几天 | 按工龄为 5 / 10 / 15 天 | 只提到司龄福利假及病假，缺失法定年休假档位 |
| 密码复杂度规范 | 至少 12 位，大小写、数字、特殊符号 | 主要输出引用标记和章节标题 |
| 代码能否上传公开仓库 | 严禁上传内部源代码 | 输出数据分级标题，缺失禁止规则 |
| 出差住宿报销标准 | 一线普通员工 500 元等 | 返回报销章节和出差审批，缺失金额 |
| 弹性打卡时间 | 30 分钟及时间范围 | 返回考勤章节标题，缺失时间 |

段落匹配采用宽松字符覆盖，并按原文顺序取前几条；标题与引用包装也参与提炼。无匹配行时还会返回前几行。回答前缀却统一声称“明确规定”，容易让用户误以为已得到完整政策答案。

建议：将引用包装与可检索正文分离，使用事实完整性和回答覆盖度的样本集验证；针对无法提炼的情况明确拒答或展示原文，不把标题当答案。哈希字符向量不具备通常语义 embedding 的能力，不能仅凭引用卡片证明回答正确。真实大模型的严格性还需单独验证，Prompt 本身不能保证“杜绝幻觉”。
